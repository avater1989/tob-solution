# 艺博 To-B 管理后台设计标准（DESIGN.md）

> 适用范围：商家管理端 / 平台运营端（PC）  
> 对标参考：小鹅通式混合导航、Ant Design Pro Layout、成熟 B2B SaaS App Shell  
> 配套产物：`docs/ToB-MVP-PRD.md`、`prototype/`  
> 版本：v1.0 · 2026-09-03

本文档是管理后台的**唯一视觉与交互标准**。原型、PRD 页面说明、后续前端实现均以此为准。C 端小程序不在本文范围。

---

## 1. 设计目标

| 目标 | 说明 |
|------|------|
| 任务优先 | 助教/运营高频切模块、扫列表、改状态，导航必须常驻、可扫读 |
| 信息架构清晰 | 一级模块与二级页面职责分离，避免「一长串侧栏」或「顶栏塞满」 |
| 数据密度可控 | 表格与指标默认信息密度偏高，但分区、留白、层级仍然清楚 |
| 可扩展 | 后续增加抖店、广告、分账等模块时，壳不需要推倒重来 |
| 信任感 | 教育 To-B 后台偏专业、克制，不做营销落地页风、不做炫光暗黑风 |

---

## 2. 参考结论（为何采用混合壳）

行业共识（SaaS 导航实践、Ant Design Pro）：

- **侧栏**适合多板块、深层级、频繁切换的管理工具。
- **顶栏**适合少量一级入口 + 全局能力（搜索、通知、账号、租户）。
- **混合壳（Top + Side）**是功能密集中后台的默认解：顶栏定「我在哪个业务域」，侧栏定「域内哪一页」。

本产品一级业务域 ≥ 5（工作台、SCRM、直播、内容、交易、用户、数据、设置），且 SCRM 内还有公域/线索/促到等子树，因此采用：

**顶栏一级模块 + 左侧二级导航 + 主内容区 +（可选）右侧操作助手。**

这与小鹅通 SCRM 类后台一致，也符合 Ant Design Pro 的 `top-mix` / 嵌套布局思路。

## 3. 应用壳（App Shell）

### 3.1 区域划分

```
┌─────────────────────────────────────────────────────────────────┐
│ Topbar：Logo · 商户切换 · 一级模块 · 全局搜索/通知/账号            │
├─────────────────────────────────────────────────────────────────┤
│ 可选 NoticeBar：系统公告 / 资质提醒 / 短信额度等（单行可关闭）      │
├──────────────┬──────────────────────────────────┬───────────────┤
│ Left Sidebar │ Main（PageHeader + Content）       │ Right Assist  │
│ 当前模块二级  │ 面包屑 · 标题 · 页级操作            │ 指引/FAQ/清单 │
│ 导航         │ 筛选条 · 指标卡 · 表格/表单/详情     │ （可折叠）     │
│              │                                    │               │
└──────────────┴──────────────────────────────────┴───────────────┘
```

| 区域 | 职责 | 禁止 |
|------|------|------|
| Topbar | 一级业务域切换 + 全局上下文 | 塞入具体列表筛选项、页内 Tab |
| Left Sidebar | **当前 Top 模块**下的页面树 | 把所有模块扁平堆进侧栏 |
| Main | 当前任务的完整工作区 | 再嵌一套与壳冲突的导航 |
| Right Assist | 上手指引、FAQ、本页相关提示 | 成为第三套主导航或塞业务表单 |

### 3.2 尺寸与行为

| Token | 值 | 说明 |
|-------|-----|------|
| Topbar 高度 | 56px | 固定吸顶 |
| NoticeBar 高度 | 36px | 有公告时出现 |
| Sidebar 宽度 | 208px（展开）/ 64px（收起图标轨） | 桌面默认展开 |
| Right Assist 宽度 | 280px | 默认可关闭；列表页可默认收起 |
| Main 最小宽度 | 960px 起适配；内容区最大阅读宽不强制限制表格 | 表格允许横向滚动 |
| 内容区内边距 | 20–24px | 统一 |

- Sidebar、Topbar **固定**；仅 Main 滚动（长表单页可整页滚，但导航不跟着丢）。
- 当前一级模块、当前二级菜单必须有明确 **Active** 态。
- 深层级（详情/编辑）用 **面包屑** 回到列表，不靠浏览器返回作为唯一手段。

### 3.3 一级模块（Topbar）信息架构

MVP 建议顺序：

1. 工作台  
2. SCRM  
3. 直播  
4. 内容  
5. 交易  
6. 用户  
7. 数据  
8. 设置（可放顶栏右侧「齿轮」或末位模块）

顶栏一级入口控制在 **5–8 个**；再多则合并（例如「交易」含订单与简易结算入口）。

### 3.4 二级导航示例（进入 SCRM 时）

```
线索管理
  · 概览
  · 线索列表
  · 分配规则（含推广期次）
公域获客
  · 视频号商品
  · 视频号订单
营销推广
  · 直播促到
```

其他模块同理：直播（列表/创建）、内容（课程列表/编辑入口）、交易（订单）、用户、数据（获客/直播/转化专题）。

非当前模块的二级项 **不得** 残留在侧栏。

## 4. 视觉语言

### 4.1 原则

- 浅色企业后台：白 / 浅灰底，安静、可读。
- 主色用于：主按钮、链接、选中态、关键指标强调；**不要**大面积品牌色铺底（概览 Hero 可用浅色渐变条，面积克制）。
- 避免：紫霓虹渐变、厚重多层阴影、圆角胶囊堆砌、暗黑默认主题。

### 4.2 颜色 Token

| Token | 值 | 用途 |
|-------|-----|------|
| `--color-bg` | `#F5F7FA` | 页面底 |
| `--color-surface` | `#FFFFFF` | 卡片、顶栏、侧栏底 |
| `--color-border` | `#E5E6EB` | 分割线、表格线 |
| `--color-text` | `#1D2129` | 主文字 |
| `--color-text-secondary` | `#4E5969` | 次级 |
| `--color-text-muted` | `#86909C` | 辅助/表头 |
| `--color-primary` | `#165DFF` | 主色（中后台蓝，接近小鹅通/Ant 系） |
| `--color-primary-soft` | `#E8F3FF` | 选中底、浅标签 |
| `--color-success` | `#00B42A` | 成功/已支付/已加微 |
| `--color-warning` | `#FF7D00` | 待处理/待审核 |
| `--color-danger` | `#F53F3F` | 失败/退款/危险操作 |
| `--color-notice` | `#FFF7E8` | 公告条背景 |

品牌若需「艺博绿」作辅助识别，仅用于 Logo 或商户角标，**交互主色仍用蓝**，保证中后台控件习惯一致。

### 4.3 字体与字号

- 字体栈：`"PingFang SC", "Microsoft YaHei", "Segoe UI", system-ui, sans-serif`
- 字号阶梯：

| 用途 | 大小 / 字重 |
|------|-------------|
| 页面标题 | 20px / 600 |
| 卡片标题 | 16px / 600 |
| 正文 / 表格 | 14px / 400 |
| 表头 / 辅助 | 12–13px / 400–500 |
| 指标大数 | 24–28px / 600 |

行高：正文 1.5；表格单元格紧凑但仍 ≥ 40px 行高。

### 4.4 圆角与阴影

| 元素 | 圆角 | 阴影 |
|------|------|------|
| 按钮 / 输入框 | 6px | 无 |
| 卡片 | 8px | `0 1px 2px rgba(0,0,0,.04)` |
| 弹层 / 抽屉 | 8px | `0 8px 24px rgba(0,0,0,.12)` |
| 标签 Badge | 4px 或胶囊 | 无 |

禁止大面积彩色投影、玻璃拟态。

### 4.5 间距

以 **8px 网格** 为准：4 / 8 / 12 / 16 / 20 / 24 / 32。  
卡片内边距 16–20px；区块间距 16px；筛选条与表格间距 12px。

## 5. 页面模式（必遵）

### 5.1 列表页（最高频）

结构顺序固定：

1. **PageHeader**：标题 + 主操作（新建/导入）+ 次要操作（导出）  
2. **FilterBar**：筛选控件单行优先，过多收入「更多筛选」  
3. **可选 StatRow**：3–4 个指标卡（与筛选项联动时需注明）  
4. **Table**：左主键信息，右操作列；状态用 Badge  
5. **Pagination**：右下角  

规则：

- 一行一个主 CTA（主色实心）；危险操作用文字/次要按钮，确认后执行。  
- 操作列最多暴露 2–3 个链接，其余进「更多」。  
- 空状态：说明原因 + 一个明确下一步（如「去关联视频号商品」）。

### 5.2 概览 / 工作台

- 顶部可有 **浅色说明条**（产品能力/待办引导），高度有限，不抢数据。  
- 指标卡 4 列栅格（大屏）；中屏 2 列。  
- 下方待办表 / 简报；时间切换用 Segmented（今日/昨日/近7日）。

### 5.3 表单 / 编辑页

- 宽度适中（单列或两列 grid），标签在上。  
- 底部操作栏：主按钮「保存/提交」+ 次按钮「取消/存草稿」，可吸底。  
- 分段用卡片标题，不滥用步骤条（除非真有强制多步）。

### 5.4 详情页

- 摘要头（状态 Badge + 关键字段）+ Tab（详情/记录/关联）。  
- 与列表、关联单据互相可点达。

### 5.5 数据看板

- 专题用 **页内 Tab** 或侧栏子项切换（获客 / 直播 / 转化）。  
- 先指标卡，后简单趋势/明细表；MVP 不做复杂自助分析器。

## 6. 组件标准

### 6.1 按钮

| 类型 | 样式 | 何时用 |
|------|------|--------|
| Primary | 蓝底白字 | 每区唯一主行动 |
| Default | 白底描边 | 次要 |
| Text | 无边框 | 表格内操作、取消 |
| Danger | 红字或红描边 | 退款、删除、驳回 |

尺寸：默认高 32px；表格内 28px。

### 6.2 表格

- 表头灰字、底部分割线；行悬停浅灰。  
- 数字右对齐；状态居中或左对齐保持列内一致。  
- 长文本截断 + Tooltip；手机号默认脱敏。

### 6.3 状态 Badge

| 语义 | 色 |
|------|-----|
| 成功/完成 | 绿底绿字 |
| 进行中/信息 | 蓝底蓝字 |
| 等待/警告 | 橙底橙字 |
| 失败/关闭 | 红底红字 |
| 中性 | 灰底灰字 |

文案短：已支付、待审核、短信失败、已加微。

### 6.4 反馈

- 轻操作成功：顶部或右上 Toast，2s。  
- 破坏性操作：Modal 二次确认。  
- 表单校验：字段下即时错误文案，提交时聚焦首个错误。

### 6.5 右侧助手（Right Assist）

适用：模块概览、首次进入 SCRM/公域配置。  
内容：3–5 条快速上手、2–3 条常见问题链接。  
列表深潜页默认收起，避免挤占表格宽度。

## 7. 导航与响应式

| 断点 | 行为 |
|------|------|
| ≥ 1440px | 四区完整；Right Assist 可开 |
| 1200–1439 | 可默认关 Right Assist |
| 992–1199 | Sidebar 可收为图标轨 |
| &lt; 992 | 管理端非 MVP 主场景；Sidebar 改抽屉，Top 模块收入「更多」 |

MVP 原型与评审以 **≥ 1280px 桌面** 为准。

---

## 8. 文案与内容

- 用业务词：线索、领课、促到、期次、加微；少用空泛「管理一下」。  
- 按钮用动词：创建直播、重发短信、保存并提交审核。  
- 占位与权限不足要说清「下一步找谁/去哪配」。  
- 公告条只放真实影响操作的信息（额度、审核、故障）。

---

## 9. 无障碍与效率（基线）

- 可聚焦控件有可见 focus 环（主色浅晕）。  
- 图标按钮必须有文案或 `aria-label`。  
- 颜色不作为唯一状态编码（配合文字）。  
- 为后续预留：全局搜索 / 命令面板（非 MVP，壳上可留搜索入口样式）。

---

## 10. Do / Don’t

**Do**

- 顶栏只放一级模块与全局能力。  
- 侧栏只反映当前模块的二级树。  
- 列表页 Filter → Table → Pagination 结构稳定。  
- 状态、渠道、金额用一致格式。  
- 主操作在视觉上唯一、可预期。

**Don’t**

- 把 SCRM、直播、课程等全部堆进左侧一棵无限长树（旧原型方式废弃）。  
- 顶栏既做模块又做页内筛选。  
- 右侧栏承载核心业务表单。  
- 指标卡超过 6 个无分组地平铺。  
- 使用营销风大插画占据首屏一半以上（说明条点到为止）。

## 11. 与 MVP 原型的落实关系

| 项 | 要求 |
|----|------|
| 壳重构 | ✅ 管理端已改为本文 §3 混合布局（`admin-shell.js`） |
| 主色 | ✅ `--color-primary: #165DFF` |
| 页面 | 仍覆盖 PRD 四条路径；SCRM 增加概览页 `scrm-overview.html` |
| C 端 | 仍用手机框模拟；不套用本文 Top+Side 壳 |
| 验收 | 打开任意管理端页，应能指出「当前一级模块 + 二级页 + 主区任务」 |
