## 1. 状态机汇总（研发与测试唯一对照表）

### 1.1 直播 · 平台审核（R-LIVE-030）

| From | To | 触发 | 前置 | 副作用 |
|---|---|---|---|---|
| 草稿 | 待平台审核 | 商家「提交平台审核」 | 必填项完整 | 编辑页锁定 |
| 待平台审核 | 审核中 | 运营接单 | — | badge 计数 |
| 审核中 | 审核通过 | 运营通过（备注选填） | — | 可上架 |
| 审核中 | 平台驳回 | 运营驳回（整改项+说明*） | — | 商家端红色横幅+定位 |
| 审核中 | 草稿 | 商家撤回 | — | 可编辑 |
| 平台驳回 | 待平台审核 | 重新提交 | 整改后 | — |

### 1.2 直播 · 执行

准备中 → 待开播 → 直播中 → 已结束 / 已取消。仅「直播中」可进中控台（R-LIVE-020）；结束触发回放生成（开启时）。

### 1.3 内容 · 上架

草稿 →（立即上架/定时到点）待平台审核 → 已上架 / 驳回（重提）；已上架 → 已下架（可再上架）；**上架后目录锁定**；平台内容商家侧恒只读。

### 1.4 订单与权益

| 对象 | 状态流转 |
|---|---|
| 订单 | 待支付 → 已支付 → 已完成；异常：已关闭（超时关单）；退款分支见售后 |
| 权益（12 态） | 待开通 → 未生效 → 有效 → 学习中 → 已学完；→ 已到期 / 已冻结（手动停用）/ 开通失败（可重试/手动）/ 已退款回收（可补开[管理员级]）/ 绑定到其他家庭成员 / 不可学习 / 不可访问 |
| 诊断链 | 订单支付→生成权益→绑定用户→已生效→过期回收→课程允许访问（六步诊断清单） |

### 1.5 售后单（知识商品口径，Q-11）

待商家处理 → 已同意（→待回收权益 → 已完成）/ 已拒绝；7 天未处理自动同意；关闭终态。

### 1.6 线索（S-3 冻结 + Q-04 收敛）

新线索 → 已分配 → 跟进中（子阶段：已加微 / 待到课）→ 已转化；旁路：无效 / 战败（须经审批）；流转态：转移申请中 / 无效申请中 / 战败申请中。

### 1.7 线索审批（P1）

待审批 → 已通过 / 已驳回；通过后联动线索阶段与归属。

### 1.8 促到 SOP 与步骤

| 对象 | 状态 |
|---|---|
| SOP | draft → scheduled → running → paused / completed / cancelled |
| 步骤 | draft / linked_booking / pending / running / completed；自动步骤状态由系统产生，人工不可直设执行中/已完成 |
| 群发任务 | 草稿 → 待执行 → 执行中 → 已完成 / 已取消 / 已失败 |

### 1.9 视频号订单

短信：待发送 → 已发送 / 失败（可重发）；领课：未领课 → 已领课；加微：未添加 → 已添加 / 已流失。

### 1.10 进件与签约（R-TRD-020）

未进件 → 资料填写 → 平台初审 → 通联审核 → 绑定手机 → 提现签约 → 可收款；异常终态：已驳回（→驳回待修改→重提）/ 已过期。约束：未绑手机不能下单；未签约不能提现。

### 1.11 对账与差异

| 对象 | 状态流转 |
|---|---|
| 对账单 | 待对账 → 已对平 / 有差异 → 待商家确认 → 已确认 / 商家已申诉（申诉暂停账期结算） |
| 差异工单 | 待处理 → 处理中 → 已平账 / 已补差 / 已挂账 / 已关闭；SLA 24h 超时升级 |

### 1.12 结算单

待商家确认 → 已确认 → 待财务复核 → 打款中 → 已打款 → 已完结；异常：已退回（复核驳回）/ 结算暂停（申诉/资金冻结）；双人复核：提交人≠复核人。

### 1.13 提现单

待审核 → 审核通过 → 打款中 → 已到账；异常：已驳回（原因*）/ 打款失败（原单重试）；风控标记强制人工。

### 1.14 发票（P1）

待开票 → 开票中 → 已开票 → 已寄出 → 已签收；可作废 / 红冲（红冲→结算单待复核或资金追偿）。

### 1.15 租户

待开通（注册留资）→ 试用中（14 天）/ 正常 → 已到期 → 停用（可恢复）；停用=后台只读+C 端下架+结算走完。

### 1.16 应用与模板角色

应用：已下架 → 灰度中 → 已上架；授权：默认/单独/试用/取消（取消=入口隐藏+接口拒绝+数据保留）。
模板角色：草稿 → 已发布 → 已下线；变更仅影响新租户。

## 4. 埋点与指标口径

### 4.1 口径原则（R-BI-001）

1. **归因口径与结果口径分离**：可归因交易只统计主漏斗关联支付；成交结果区为全量支付事件（含未归因）。
2. **GMV**=已支付金额（含退款冲减）；退款率=退款金额/GMV。
3. **视频号获客首单**为辅口径，不进私域后链路漏斗。
4. **促到到课差**只标注相关性，不表述因果。
5. 消费摘要（用户列表）=近 30 天口径；资产入账按支付时间。
6. 期次复盘必须锚定单一期次；「全部期次」禁止复盘。
7. 暂无投放成本数据：**不展示 CAC/ROI**。

### 4.2 关键漏斗定义

| 漏斗 | 层级 |
|---|---|
| 端到端（总览） | 私域池 → 已加微 → 有到场 → 可归因支付 |
| 期次复盘 | 入池 → 分配 → 加微 → 跟进 → 到场 → 支付 |
| SOP 单场 | 目标 → 触达 → 预约 → 到场 → 支付（+触达成本） |
| 直播单场复盘 | 目标 → 邀约 → 推送成功 → 到场 → 有效观看 → 支付 |
| C 端内容 | 曝光 → 详情 → 试看 → 下单 → 支付 → 学习（小程序数据页） |

### 4.3 埋点事件清单（最小集）

| 域 | 事件 |
|---|---|
| C 端 | shop_enter（带 shop 参）、course_view、trial_play_end、buy_click、pay_success(from)、live_enter、ticket_buy、claim_success(批次/来源码)、learn_progress、mark_complete |
| 商家端 | lead_create/import、assign_execute(规则命中层级)、followup_write、sop_start/sop_step_send(渠道)、live_submit_review、live_start/end、content_shelf_submit、order_refund(类型)、entitlement_retry、phone_decrypt(原因) |
| 运营端 | audit_submit/pass/reject(原因枚举)、recon_diff_dispose(动作)、settle_confirm/launch_pay、payout_review(标记)、tenant_create/suspend |
