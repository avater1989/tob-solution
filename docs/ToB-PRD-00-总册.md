## 1. 背景与目标

### 1.1 战略背景

艺博从 B2C 家庭教育服务升级为 **B2B2C 行业赋能平台**：将技术、内容、获客方法论打包输出给家庭教育机构与从业者（IP），开辟第二增长曲线。战略细节见概念设计文档；**本期不以概念设计七大板块全家桶为研发范围**。

### 1.2 本期核心命题

**如何让几个 IP 快速上线并可用。**

不以「对标小鹅通 / 螳螂全量功能」为目标，而以试点商户能完成：

**上架内容 → 开播转化 → 视频号承接 → 私域跟进**（+ 平台开通与审核）

的最短闭环为目标。

### 1.3 目标用户与典型客户

| 侧 | 对象 | 说明 |
|----|------|------|
| B 端 | 家庭教育机构 / IP（商户/租户） | 使用商家管理端经营获客、直播、内容、交易 |
| B 端 | 平台运营 | 使用运营后台开通租户、套餐、审核 |
| C 端 | 家长 / 学员 | 使用独立 To-B 小程序看课、进直播、购买、领课、学习 |

> 首批试点 IP 名单与上线窗口见开放问题 **D8**（未补齐则「快速上线」无法业务验收）。本文不杜撰 IP 名称或 OKR 数字。

### 1.4 成功标准

**业务成功（试点期，待 D8 补齐后量化）**

- 试点商户能在约定窗口内完成主路径①–④的真实业务闭环。
- 平台侧能完成租户开通、套餐生效与直播/内容审核（路径⑤）。

**评审 / 研发验收标准（与业务指标分开）**

| 编号 | 标准 |
|------|------|
| S1 | 可用浏览器按本册第 5 章逐步用例走通主路径①–⑤（原型可无后端） |
| S2 | P0 / P1 / 不做 与冻结表建议一致；原型超范围页在分册标 P1/不做，不进发布检查清单 |
| S3 | 「完整方案有、本期没有」写入非目标，防止范围回潮 |
| S4 | 关键状态机（线索、直播审核、订单权益）与权限原则已写（细表见分册/附录） |

### 1.5 本期非目标总表（防回潮）

| 类别 | 明确不做（本期） |
|------|------------------|
| 公域扩展 | 抖店 / 小红书完整链路、广告投放、素材中台 |
| 直播形态 | H5 直播主路径（见 D1 建议默认：一期仅独立小程序；H5 进路线图） |
| 内容套件 | 艺博士强制入口、测评、定制化计划、读书会 / 线下课 / OMO |
| 店铺 | 可视化楼层装修器（仅固定模板 + 少量配置，见 D7） |
| 交易财务 | 完整多方分账规则引擎、对账异常工单、提现管理、发票/资金风控全家桶（见 D2/D6） |
| SCRM 灰产与授权页 | 企微服务商改造配置页、小店/企微授权配置页、会话存档、RPA 全自动拉群 |
| 其他 | 完整工单中心（仅保留快捷任务）；系统计费引擎（技术服务费一期手工/合同，见 F4） |

## 2. 术语与假设

### 2.1 术语表

| 术语 | 定义 |
|------|------|
| 商户 / 租户（tenant） | 入驻平台的机构或 IP；数据按商户隔离 |
| 推广期次 | 按时间窗组织的获客活动单元；与渠道、商品、分配规则绑定 |
| 领课 | C 端用户凭短信/链接兑换课程或权益的动作 |
| 促到 | 直播前/中对线索的到课触达（本期以短信为主） |
| 备付金分账 | 支付进入平台备付金后再向商户分账的链路一示意 |
| To-B 小程序 | 与「大于众学」分离的独立 C 端小程序 |
| 企业内部应用 | 企微侧以企业内部应用方式使用 SCRM；服务商身份未落实前不做第三方应用改造页 |
| 路径①–⑤ | 本册第 5 章端到端验收真源 |

### 2.2 多租户与数据隔离假设

- 每个 IP / 机构为独立商户，**数据按商户隔离**。
- 平台运营可跨租户只读全局订单等治理数据（深度见 D4）。
- C 端带参进店，**减少跨店铺切换**；不对商户承诺「上帝视角」拓客能力（见 F3）。

### 2.3 资质与合规假设（依赖状态）

| ID | 依赖项 | 建议写法 / 假设状态 | 对上线影响 |
|----|--------|---------------------|------------|
| E1 | 艺博 EDI + 《信息网络传播视听节目许可证》 | **依赖**：未具备则不可对外部宣称可播 | 上线门禁 |
| E2 | 企微服务商 / 第三方应用身份 | **未落实（假设）** → SCRM 保持企业内部应用 + 授权关联 | 不挡 P0 页面；挡服务商改造 |
| E3 | 视频号小店授权 | 一期**部署同步**；配置页不做（P1/不做） | 不挡主路径③示意 |
| E4 | 持牌支付 / 通联等进件与分账合同 | **未定（假设）**；决定 D2 能否落地 | 交易真实收款 |
| E5 | 短信（及是否外呼）供应商 | 促到 P0 以短信为主；外呼额度 P1 | 促到触达 |

### 2.4 系统边界

| 系统 | 边界说明 |
|------|----------|
| 大于众学 | 艺博自营 C 端；与 To-B 小程序信息架构分离，不混用账号体系作为本期交付 |
| 定制化中心 | 艺博内部内容/计划中台；To-B 多租户内容系统 ≠ 定制化中心；同步机制原则 P1 |
| 客户中心（现网驾驶舱） | SCRM 对标来源；本期保留通用能力并按冻结表裁剪验收，去艺博业务强绑定 |

## 3. 角色与三端

### 3.1 角色清单

| 角色 | 端 | 职责摘要 |
|------|----|----------|
| 平台运营 | 运营后台 | 租户开通、套餐、直播/内容审核、全局订单只读 |
| 商户管理员 | 商家管理端 | 内容上架、直播创建、SCRM 配置、订单与用户、看板 |
| 助教 / 销售 | 商家管理端 | 线索跟进、促到执行、手动打标、群发基础 |
| 主播 / 助播 | 商家管理端（直播中控） | 开播预检、基础互动、挂载商品（细则见直播分册） |
| 审核员（平台） | 运营后台 / 复用审核工作台 | 直播/内容审核通过或驳回（驳回必填理由） |
| C 端用户 | To-B 小程序 | 看课、进直播、购买、领课、学习 |

### 3.2 端 × 角色矩阵

| 角色 | 商家端 | 运营端 | C 端 |
|------|--------|--------|------|
| 平台运营 | — | ✓ | — |
| 商户管理员 | ✓ | — | — |
| 助教 / 销售 | ✓ | — | — |
| 主播 / 助播 | ✓（直播相关） | — | — |
| 审核员 | 视部署可只读预览 | ✓ | — |
| C 端家长 | — | — | ✓ |

### 3.3 权限原则（细表放附录 / 分册）

- **最小可用**：账号 / 部门 / 角色 / 基础权限为 P0；精细权限树 P1。
- **审核禁区**：未审核通过的直播禁止开播；驳回必须填写理由。
- **租户隔离**：商户成员不可跨租户读写线索、订单、用户。
- **SCRM**：未落实企微服务商前，不提供授权配置页；能力以企业内部应用可用范围为限。

## 5. 端到端主路径（验收真源）

> 终版以主路径验收，不以菜单穷举验收。  
> 每条路径：触发 → 关键步骤 → 系统结果 → 异常分支 → 验收用例。

### 5.1 路径① 内容售卖（P0）

**触发**：商户管理员要上架一门可售线上课并完成一笔 C 端购买。

**关键步骤**

1. 商家端创建系列课/单课（标题、封面、目录、价格、试看、排序）并上架。  
2. C 端首页展示该课；用户进入详情可试看。  
3. 用户下单并完成小程序支付。  
4. 系统开通学习权益；「我的 / 学习」可学。

**系统结果**：订单状态=已支付；权益=已开通；C 端可学。

**异常分支**

- 课程未上架 → C 端不可见或不可购。  
- 支付失败 → 订单待支付/关闭；权益不开通。  
- 退款成功 → 权益回收（详见交易分册）。

**验收用例**

| 编号 | Given / When / Then |
|------|---------------------|
| AC-①-01 | Given 商户已创建并上架系列课，When C 端打开首页，Then 可见该课入口 |
| AC-①-02 | Given 用户在课程详情发起购买且支付成功，When 进入「我的」，Then 可见已购并可进入学习 |
| AC-①-03 | Given 订单已支付后发起退款且退款成功，When 查看权益，Then 权益已回收、学习入口关闭或不可学 |

### 5.2 路径② 直播转化（P0）

**触发**：商户创建一场可售/可看直播，经平台审核后 C 端观看并购课。  
**假设**：D1=A（独立小程序直播）。

**关键步骤**

1. 商家端创建直播（可设付费/挂载商品）并提交审核。  
2. 平台审核通过（驳回则改后重提）。  
3. C 端直播 Tab 进入预告/直播间；基础评论与商品栏可用。  
4. 用户直播间购课 → 权益开通。

**系统结果**：审核状态=已通过；执行态可达直播中；成交订单与权益闭环。

**异常分支**

- 待审核/已驳回 → 不可开播。  
- 开播前校验未通过审核 → 禁止开播。  
- 观看权限不满足 → 引导购买或无权限提示。

**验收用例**

| 编号 | Given / When / Then |
|------|---------------------|
| AC-②-01 | Given 直播在草稿，When 业务提交审核，Then 状态=待审核且内容锁定 |
| AC-②-02 | Given 待审核直播，When 审核员通过，Then 状态=已通过且可进入开播准备 |
| AC-②-03 | Given 已通过且直播中，When C 端用户进入直播间并购买挂载课，Then 支付成功且权益开通 |
| AC-②-04 | Given 待审核或已驳回，When 主播尝试开播，Then 系统拒绝并提示原因 |

### 5.3 路径③ 视频号获客承接（P0）

**触发**：用户在视频号下单（外部）后，商户需完成领课短信与加微回写，并进入线索分配。

**关键步骤**

1. 外部视频号订单同步至商家端「视频号」页可见。  
2. 系统/运营发送领课短信（失败可重发）；可复制领课链接。  
3. C 端领课页兑换成功；可选引导加微。  
4. 领课/加微状态回写；线索进入分配池（衔接到路径④）。

**系统结果**：订单可见短信/领课/加微状态；线索可被规则分配。

**异常分支**

- 短信失败 → 可重发；记录失败原因。  
- 重复领课 → 幂等提示已兑换。  
- 小店授权未配置页 → 依赖部署同步（E3），不在 P0 做配置页。

**验收用例**

| 编号 | Given / When / Then |
|------|---------------------|
| AC-③-01 | Given 视频号侧已产生订单并完成同步，When 打开 `videos.html`（订单视图），Then 可见订单号/手机号（脱敏）/商品/支付/短信/领课/加微状态 |
| AC-③-02 | Given 短信未发或失败，When 操作重发领课短信，Then 发送状态更新为成功或再次失败并留痕 |
| AC-③-03 | Given 用户打开领课链接并兑换成功，When 回看订单与线索，Then 领课状态=已领，且线索可进入分配 |
| AC-③-04 | Given 商品已关联平台课/直播商品并配置领课模板，When 新订单进入，Then 可按配置触发领课链路 |

### 5.4 路径④ 私域运营（P0）

**触发**：已入库线索需按推广期次分配、促到、跟进打标，并在看板可见。

**关键步骤**

1. 配置推广期次与分配规则（渠道 × 商品 × 期次 → 成员/分组；轮询/上限）。  
2. 线索自动或批量分配给助教；跟进管理可记录跟进。  
3. 创建直播促到 SOP（短信为主）并执行触达。  
4. 用户详情/线索上手动打标；经营分析看板查看获客/到课/转化摘要。

**系统结果**：线索有跟进人与状态迁移；促到任务有触达结果；看板有关键指标。

**异常分支**

- 无匹配规则 → 进入待分配。  
- 短信额度不足/失败 → 任务标记失败可重试。  
- 重复线索 → 合并后只保留一条主线索，跟进人/期次不丢，可追溯合并记录（AC-④-06 / `leads-dup.html`）。

**验收用例**

| 编号 | Given / When / Then |
|------|---------------------|
| AC-④-01 | Given 已创建推广期次并配置渠道×商品×期次规则，When 新线索入库匹配成功，Then 自动分配到指定成员或进入轮询 |
| AC-④-02 | Given 助教拥有已分配线索，When 填写跟进记录，Then 最近跟进时间更新且状态可进入跟进中 |
| AC-④-03 | Given 已选直播与人群创建促到计划，When 执行短信触达，Then 可查看成功/失败及未到课名单示意 |
| AC-④-04 | Given 线索已加微或已领课，When 在详情手动打标，Then 标签在线索/用户视图一致可见 |
| AC-④-05 | Given 路径③④产生订单与跟进数据，When 打开获客/直播/转化看板，Then 可见订单数、领课率、加微率等关键指标（轻量） |
| AC-④-06 | Given 存在命中去重规则的重复线索组（页面 `leads-dup.html`），When 选择主线索并确认合并成功，Then 重复线索合并成功后只保留一条主线索、跟进人/期次不丢、可追溯合并记录 |

### 5.5 路径⑤ 平台侧：租户开通 → 套餐生效 → 审核（P0）

**触发**：平台要为新 IP 开通租户并使其可提交直播/内容审核。  
**假设**：D4=A + 全局订单只读。

**关键步骤**

1. 运营后台创建/开通租户，配置套餐并生效。  
2. 商户管理员可登录商家端（账号最小集）。  
3. 商户提交直播或内容审核 → 平台审核通过/驳回。  
4. （可选检查）全局订单只读可按租户查看。

**系统结果**：租户可用；套餐配额生效；未审过不能开播/按规则不能上架。

**异常分支**

- 套餐未生效 → 商户关键能力不可用或只读。  
- 审核驳回 → 必须理由；商户可改后重提。

**验收用例**

| 编号 | Given / When / Then |
|------|---------------------|
| AC-⑤-01 | Given 运营录入新租户并生效套餐，When 商户管理员登录，Then 进入商家端且数据隔离在本租户 |
| AC-⑤-02 | Given 商户提交直播审核，When 运营在审核工作台通过，Then 商户侧状态=已通过 |
| AC-⑤-03 | Given 商户提交被驳回，When 查看详情，Then 可见驳回理由且可编辑后重新提交 |
| AC-⑤-04 | Given 存在跨租户订单，When 运营打开全局订单，Then 只读可见且不可替商户改单 |
