## 1. 背景与目标

### 1.1 战略背景

艺博从 B2C 家庭教育服务升级为 B2B2C 行业赋能平台：将技术、内容、获客方法论打包输出给家庭教育机构与从业者（IP），开辟第二增长曲线并强化行业生态卡位。

### 1.2 MVP 核心命题

**如何让几个 IP 快速上线并可用。**

不以「对标小鹅通/螳螂全量功能」为目标，而以「试点商户能完成：上架内容 → 开播转化 → 视频号承接 → 私域跟进」最短闭环为目标。

### 1.3 成功标准（内部评审）

| 编号 | 标准 |
|------|------|
| S1 | 评审可在无后端情况下，用浏览器走通 4 条主路径 |
| S2 | PRD 页面与原型一一对应，研发可据此估工期 |
| S3 | 「完整方案有、MVP 没有」项写清，降低范围回潮 |

## 2. 角色与多租户假设

### 2.1 角色

| 角色 | 端 | 职责 |
|------|----|------|
| 平台运营 | 管理端（平台视角示意） | 商户入驻、渠道配置、直播审核、全局风险 |
| 商户管理员 | 管理端 | 内容上架、直播创建、订单与用户管理、看板 |
| 助教 / 销售 | 管理端 | 线索跟进、直播促到、手动打标 |
| C 端家长 | To-B 小程序 | 看课、进直播、购买、领课、学习 |

### 2.2 多租户

- 每个 IP / 机构为独立商户（tenant），数据按商户隔离。
- MVP 原型以「示例商户：星启家庭教育」演示；平台侧能力仅作菜单/状态示意。
- C 端为独立 To-B 小程序（与「大于众学」分离），支持后续按主体剥离部署。

## 4. 端到端主路径（验收路径）

### 路径 1：内容售卖

管理端创建并上架线上课 → C 端首页可见 → 课程详情试看/购买 → 支付成功 → 我的可学。

### 路径 2：直播转化

管理端创建直播（可设付费）→ 平台审核通过 → C 端直播 Tab 进入 → 互动示意 → 直播间购课 → 权益开通。

### 路径 3：视频号获客承接

用户在视频号下单（外部）→ 管理端视频号订单可见 → 发送领课短信 → C 端领课页兑换 → 加微状态回写 → 线索进入分配。

### 路径 4：私域运营

线索按推广期次/规则分配给助教 → 创建直播促到任务 → 短信触达 → 用户详情手动打标 → 看板查看获客/到课/转化。

### 5.3 直播

**P0**

- 多租户下商户创建直播：标题、封面、开播时间、主讲、观看权限（免费 / 需购买 / 指定权益）
- 直播可作为独立商品售卖（价格、上下架）
- 平台审核：待审 / 通过 / 驳回（多商户内容安全底线）
- C 端：列表、预约/进入、基础评论、商品栏、购买弹层
- 保留录像意图说明（安全留痕）；完整内容安检后续

**P1（原型可点示意）**：抽奖、红包、氛围组、助教控制台完整能力（与大于众学同步升级项）。

**技术约束（写入风险）**

- MVP 采用小程序直播方案加速；完整方案优先 H5（违规封禁面更可控）。
- 艺博侧需关注 EDI、网文等相关资质；IP 主体未必具备小程序直播资质。

#### 5.3.1 直播审核流程（P0 新增）

**业务背景**

业务人员（销售 / 运营）创建直播后，需经过管理端审核员审核通过才允许上架开播。审核不通过时需明确驳回理由，业务人员可修改后重新提交。

**状态机**

```
草稿 ──提交──▶ 待审核 ──通过──▶ 已通过（自动上架，可开播）
                  │                │
                  └──驳回──▶ 已驳回（业务人员编辑后重新提交）
                                   │
                                   └──重新提交 → 待审核
已通过 ──管理端强制下架──▶ 已取消（终态）
```

| 状态 | 业务人员可操作 | 审核员可操作 | 备注 |
|------|--------------|------------|------|
| 草稿 | 编辑 / 提交审核 / 删除 | — | 仅自己可见 |
| 待审核 | 撤回（→草稿） | 通过 / 驳回 | 锁定编辑，不可改内容 |
| 已驳回 | 编辑 / 重新提交 | 查看驳回记录 | 展示驳回理由 |
| 已通过 | 取消上架 | 强制下架 | 可上架开播 |
| 已取消 | 复制 | — | 终态 |

**新增/改造页面**

| 页面 | 文件 | 说明 |
|------|------|------|
| 直播列表 | `lives.html` | 改造：新增「审核状态」列（5 种徽标：草稿/待审核/已通过/已驳回/已取消）、筛选区加「审核状态」、4 个统计卡片、行操作按状态变化 |
| 创建/编辑直播 | `live-edit.html` | 改造：URL 加 `?status=pending\|rejected` 携带状态；驳回状态顶部红色横幅（驳回理由/审核人/时间）+ 提交按钮改为「重新提交审核」；待审核状态黄色横幅（只读）+ 「撤回审核」按钮 |
| 审核工作台 | `live-audit.html` | 新增：4 统计卡（待我审核 / 今日已审核 / 平均审核时长 / 驳回率）；3 Tabs（待我审核带红点 badge / 我已审核 / 全部）；筛选齐全；批量通过；表格行等待时长彩色徽标（新鲜 / 警告 / 超时） |
| 审核详情 | `live-audit-detail.html` | 新增：左侧直播完整信息只读预览（基本信息/封面/设置/挂载商品/售卖方式 5 段）；右侧审核侧栏（当前状态 + 审核维度 4 项勾选 + 审核意见 textarea + 通过/驳回/取消按钮 + 审核历史时间轴含驳回理由）；通过弹窗确认；驳回需填理由 |
| 驳回记录 | `live-rejected.html` | 新增（二期）：业务人员视角：所有被驳回的直播列表，含驳回理由，关联到原直播的编辑入口 |

**侧栏导航**

`admin-shell.js` 直播模块新增分组「直播审核」：

- 审核工作台（带红点 badge 显示待审核数）
- 驳回记录
- 审核详情

**数据模型建议**

```
live_streams (扩展)
  + audit_status       ENUM('draft','pending','approved','rejected','cancelled')
  + audit_comment      VARCHAR(500)    -- 最近一次驳回理由
  + auditor_id         BIGINT          -- 最近审核人
  + audited_at         DATETIME        -- 最近审核时间
  + submitted_at       DATETIME        -- 提交审核时间

live_audit_logs (新增)
  id, live_id, auditor_id, action(approve/reject/withdraw/takedown),
  comment, created_at
```

**权限矩阵**

| 角色 | 创建直播 | 提交审核 | 审核操作 | 强制下架 |
|------|---------|---------|---------|---------|
| 业务人员 | ✓ | ✓ | ✗ | ✗ |
| 审核员 | ✗ | ✗ | ✓ | ✓ |
| 管理员 | ✓ | ✓ | ✓ | ✓ |

**通知触达（MVP 站内信，二期接入企微）**

- 业务人员：提交成功 → 「待审核」通知；审核通过 → 「已上架」通知；审核驳回 → 「驳回通知（带理由）」
- 审核员：新提交到达 → 「待我审核」通知
- 开播前 1 小时校验审核状态，未通过的禁止开播

**MVP 边界**

- ✅ 必做：5 种状态机 + 列表筛选 + 工作台 + 详情审核 + 驳回编辑重新提交流程 + 侧栏 + 权限
- ⚠ 暂缓（二期）：驳回记录独立页、批量驳回（只做批量通过）、自动审核 AI 预检、企微通知集成、跨租户审核池

### 5.4 内容中心

**P0**

- 商户创建单课或系列课：标题、封面、目录、价格、试看节、上下架、排序
- C 端固定模板：首页（Banner + 课程列表）、直播 Tab、我的
- 不做店铺装修、不做定制化/艺博士强制入口

**内容与内部定制化中心关系（架构原则）**

### 5.5 交易

**P0**

用户交易链路：确认订单 → 支付 → 订单生成 → 权益开通 → 退款与权益回收。

| 能力 | MVP |

| 支付 | 微信小程序支付示意 |

| 退款 | 申请/审核/原路退/关权益（简化状态） |

**非目标**：完整多方分账规则引擎、对账异常工单、提现管理后台。

### 5.6 用户中心

公域订单用户应进入同一用户视图。

## 6. 关键状态机（简化）

### 6.1 线索

`新建` → `已分配` → `跟进中` → `已加微` / `已领课` → `已转化` / `已流失`

### 6.2 直播

`草稿` → `待审核` → `已通过` → `预告中` → `直播中` → `已结束`（可回放示意）  
驳回：`待审核` → `已驳回` → 修改后重新提交。

### 6.3 订单与权益

`待支付` → `已支付` → 触发 `权益已开通`  
`退款中` → `已退款` → 触发 `权益已回收`  
视频号订单另有：`短信状态`、`领课状态` 与平台订单关联。
