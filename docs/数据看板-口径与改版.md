# 商家端数据看板 — 口径说明与改版提纲

> 适用范围：`prototype/admin/board-*.html`  
> 目标：评审可讲清「转化率是多少」，专题可定位漏损，并与工作台分工。

---

## 1. 与工作台的边界

| | 工作台 | 数据看板 |
|--|--------|----------|
| 问题 | 今天做什么 | 这一环漏在哪 |
| 时间 | 默认今日 | 默认近 7 日（可切 30 日 / 今日） |
| 形态 | 待办 + 入口 | 同口径漏斗 + 归因明细 |
| 不做什么 | 不做渠道/期次深度对比 | 不做待办清单 |

---

## 2. 主口径：入池线索 Cohort

**定义：** 统计期内，首次进入本商户「线索池」的线索（去重后）。

**近 7 日示意主链（全文统一用这组数）：**

```
入池 612
  → 已分配 589（96%）
  → 已加微 392（分配后 67% / 入池 64%）
  → 支付成功 128 人（加微后 33% / 入池 21%）
```

**旁路（不进主漏斗）：**

- 到课：已加微中有到课 186（直播专题 / 总览旁路卡）
- 跟进：覆盖率、无跟进数（跟进专题，主链质量环节）
- 退款：退款率 / 退款用户（转化旁路）

说明：

- 业务主链叙事仍是「获客 → 承接 → 跟进 → 直播 → 转化」。
- 漏斗百分比默认标注为 **相对上一步**；「入池→支付」另标 **相对入池**。
- 「支付成功」按 **支付用户数（去重）**；订单数 / GMV 单独展示。
- **到课、退款、ROI 不进主漏斗**；转化页用「到课/未到课成交」证明可不经到课成交。
- **归因：** 统计期内首次入池的线索，观察其在统计期内是否完成分配 / 加微 / 支付。

### 2.1 辅口径（必须打标，禁止与主链混加）

| 辅口径 | 用于 | 示意 |
|--------|------|------|
| 视频号订单 | 获客 / 承接-领课 | 订单 286 → 流入线索 241 → 领课成功 198 |
| 直播场次 | 直播专题 | 场次、预约、到课率、促到提升（按场次） |
| 内容课订单 | 转化排行 | GMV / 订单，不强制并进主链每一步 |

## 3. 五专题职责（互斥指标）

| 专题 | 只回答 | 主指标 | 禁止重复 |
|------|--------|--------|----------|
| 总览 | 全链路哪里漏得最多 | 主链 4 步漏斗 + 到课/跟进旁路 | 不做渠道大表 |
| 获客 | 人从哪来 | 入池量、渠道结构、视频号订单→入池 | 不加微/成交 |
| 承接 | 接住了吗 | 待分配、分配及时率、加微率；领课用视频号辅口径 | 不做跟进次数/SOP |
| 跟进 | 私域有没有推进（质量专题） | 覆盖率、阶段、人效、流失 | 不进主漏斗台阶 |
| 直播 | 场次是否有效 | 场次到课、促到提升 + 加微人群到课旁路 | 不讲 GMV |
| 转化 | 钱与退款 | 支付漏斗（对齐总览）+ 到课/未到课成交拆分 + 退款旁路 | 不讲分配积压 |

---

## 4. 版式差异（避免五页同构）

| 专题 | 主视觉 | 次要 | 明细 |
|------|--------|------|------|
| 总览 | 主链大漏斗 | 掉点卡片 3 个 | 链路上的「去专题」 |
| 获客 | 渠道占比表 / 条形 | 视频号辅漏斗 | 渠道×期次表 |
| 承接 | 分配→加微漏斗 | 分配时效 | 跟进人承接表 |
| 跟进 | 阶段分布 | 人效表为主 | 流失/待办入口 |
| 直播 | 场次对比表为主 | 促到效果卡 | 入池到课率旁注 |
| 转化 | 支付漏斗（至支付） | GMV 趋势 | 商品排行；退款独立卡 |

交互约定：

- 侧栏保留专题；**页顶链路条改为精简文字**（总览可保留完整链）。
- 筛选变更时，示意数字至少切换「近 7 日 / 近 30 日」两套（原型级）。
- 主指标卡可点击进入对应业务列表。
