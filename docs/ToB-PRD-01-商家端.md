## 1. 工作台

### 1.1 模块目标
商户管理员打开后台第一屏即看到经营结果与今日必须处理的事。

### 1.2 页面与交互：`dashboard.html`（P0）

- **页面目的**：经营结果 + 实时待处理聚合（2026-09-18：待办中心下线；2026-09-19：两个区域标题行下线，页面直接以统计卡开始）。
- **结构**：
  1. 经营结果统计卡（受时间筛选），**按业务域分组**：SCRM·线索（新增线索 / **未分配线索**）/ 交易（支付订单 / 成交 GMV / 退款率 / **待处理售后**）（点击跳对应列表页）。
  2. 实时待处理统计卡（不受时间筛选），**按业务域分组**：直播（直播待提交／待修改、直播提醒异常）；**点击卡片直接跳对应列表页**（线索池 / 直播列表 / 直播促到 / 售后列表）。
  3. 快捷创建入口（创建直播/创建课程/新建线索）。
  4. 时间粒度切换：今日 / 昨日 / 7 日。
- **2026-09-19 调整**：

## 4. 内容

### 4.1 模块目标
商家自建知识内容（系列课/视频/图文）并上架售卖；平台标准内容可分享复用；测评与定制化计划为转化辅助（P1）。

### 4.2 内容管理（P0）

#### 内容 / 商品 / 上架 三层模型（2026-09-21 口径重构）

> 本次重构解决两个历史耦合：① 内容实体内嵌价格，导致「一个内容只能一个价」；② 试看与免费/付费写在内容上，导致同一内容无法在不同小程序模块采用不同售卖策略。

| 层 | 实体 | 职责 | 是否含价格 |
|---|---|---|---|
| 1 | **内容 Content** | 知识资产本身：线上课 / 线下课 / 文章 / 定制化计划 / 直播；含章节、讲师、封面、简介等 | **否** |
| 2 | **商品 Goods** | 唯一价格载体：定价、划线价、交付方式、退款规则、平台审核态 | **是** |
| 3 | **上架位 Listing** | 内容在小程序模块的售卖策略：免费/付费、试看范围、下单方式、成交商品、排序、显隐 | 否（引用商品的价） |

- **关系权威源**：商品侧 `contents[]`（2026-09-21 由单一 `content_id` 扩展为数组）。内容↔商品为 **M:N**：
  - **1 内容 : N 商品** —— 同一内容可建多个不同价/不同交付方式的商品；
  - **1 商品 : N 内容** —— **组合商品**（如「1 门线上课 + 1 篇文章」礼包）；
  - 1 内容 : N 上架位（同一内容可上架到多个模块，各自独立配置）；
  - 兼容字段：商品的 `content_id` / `content_type` 恒等于 `contents[0]`（主内容），仅供旧字段与订单快照读取。
- **内容侧不再有 `price` 字段**；旧数据迁移到 `_legacyPrice` 仅用于「待补建商品」人工核对，界面不渲染。
- **试看的两层分工**（消除双源）：
  - `chapter.free` = **内容结构属性**，作者声明「本节允许被试看」，随内容审核；
  - `listing.trial_scope` = **售卖策略**，本次上架实际开放多少试看，**不得超出** `chapter.free` 的范围。
- 内容编辑页新增「**关联商品**」页签：只读展示交付了该内容的全部商品（名称 / 价格 / 审核态 / 上架态 / 被哪个上架位指定为成交商品）——**组合商品也会命中**；并提供「+ 新建商品」深链。

列表只表达「内容自身 + 关联商品数 + 上架状态」，不再重复售卖信息（售卖在商品与上架位）：

## 6. 交易

### 6.1 模块目标
知识商品下单、支付、权益开通与售后的完整商家侧闭环；资金链路对接通联（弱存管+托管代收/付），商家侧可见对账与结算结果。侧栏含 **店铺运营**（首页装修 / 我的页 / 店铺设置）。

### 6.2 费率口径基准（R-TRD-000，全端唯一）

| 项 | 值 | 说明 |
|---|---|---|
| 入金手续费 | 0.3% | 通联收取，按笔，退款返还 |
| 链路 A（平台内容） | 商家佣金 20%，平台留存 80% | 平台内容订单 |
| 链路 B（自建内容） | 平台服务费 0.6%，商家应结 99.4% | 自建内容订单 |
| 提现费 | 1 元/笔；实名认证 5 元/次 | 通联报价 |
| 废弃口径 | 1% / 2% / 10% / 12% / 15% / 5% / 0.28% | 不再出现（Q-01） |

**分账算法（R-TRD-001，2026-09-19 修正）**：`base = 实付 − 累计退款`（分账基数，净计收）；
- **链路 A（平台内容·佣金模式）**：商家所得 = base × 佣金率（默认 20%），平台留存 = base − 商家所得（即 80%）；
- **链路 B（自建内容·服务费模式）**：平台所得 = base × 服务费率（默认 0.6%），商家应结 = base − 平台所得（即 99.4%）；
- 分账金额四舍五入到分；`channelFee = 实付 × 0.3%`（入金手续费，渠道成本，**不参与分账**，单列展示）；
- 分账状态：已退款=「已冲正（清分回退）」，退款处理中=「已冻结（暂缓分账）」，未支付=「不产生分账」，免费场次=「无分账金额」，正常=「待分账 T+1 自动分账」。

> 历史问题（2026-09-19 修正）：本节原文写作「链路 A 平台所得 = base×20%」，与上方口径表「链路 A 商家佣金 20%、平台留存 80%」相反，导致原型按错误公式实现（把 80% 的金额标成商家所得）。现按口径表改正，原型同步修正。
> 历史订单按规则快照结算；改规则仅对修改后支付的订单生效。
